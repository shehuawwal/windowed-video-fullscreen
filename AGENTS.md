# AGENTS.md

Guide for AI coding agents and human contributors. Read it before changing code.

## What this is

A WebExtension (Manifest V3) that replaces the page's Fullscreen API so video "fullscreen" fills the browser tab instead of the screen. One source tree in `src/` builds for Chromium browsers and Firefox. Safari is built from the Chromium output with Apple's converter.

No bundler, no npm dependencies, no transpiling. Plain browser JavaScript, loaded as-is.

## Layout

```
src/
  page.js              MAIN-world content script: patches the Fullscreen API, does the layout, shortcuts, frame protocol
  bridge.js            isolated-world content script: storage -> page.js, popup commands -> page.js
  shared/settings.js   defaults, merge/validation, shortcut labels (global WVFS; also require()-able in Node)
  shared/ui.css        styles shared by the popup and options page
  popup/               toolbar popup (toggle, per-site and global on/off)
  options/             settings page (shortcut recorder, behaviour, disabled sites)
  icons/               generated by scripts/make-icons.py; don't edit the PNGs by hand
manifests/
  chrome.json          Chromium manifest (Chrome, Edge, Brave, Opera, Vivaldi, Arc)
  firefox.json         same plus browser_specific_settings.gecko
scripts/
  build.sh             src/ + manifest -> dist/<browser>/ and dist/*.zip
  safari.sh            dist/chrome -> Xcode project (macOS)
  make-icons.py        draws src/icons/*.png with no dependencies
tests/
  settings.test.mjs    node --test unit tests for shared/settings.js
  harness.html         behaviour tests: loads src/page.js into a real page
  run-harness.sh       runs harness.html in headless Chrome, prints pass/fail
demo/index.html        manual test page (native controls, bad player, transformed feed, link wrapper, iframe)
docs/PLAN.md           roadmap and design decisions
```

## How it works

1. **page.js** runs at `document_start` in the page's MAIN world, in every frame. It saves the native Fullscreen API and replaces:
   - `Element.prototype.requestFullscreen` (plus `webkit`/`moz` variants and `HTMLVideoElement.webkitEnterFullscreen`), which now calls `enter()`.
   - `Document.prototype.exitFullscreen` (plus variants), which now calls `exit()`.
   - Getters `fullscreenElement`, `fullscreen`, `fullscreenEnabled` and variants, which report our state.

   When the extension is off (globally, for this site, or for the parent frame's site), every patched function falls through to the native one.

2. **Layout, "in place" (default).** The target (the requested element, or a player wrapper around a bare `<video>`, see `findPlayerTarget`) gets `position: fixed` and covers the viewport. Ancestor properties that would trap a fixed element (transform, filter, contain, container-type and so on; see `ANCESTOR_FIX`) are neutralised, and ancestors get a maximum `z-index`. The video and every wrapper between it and the target are sized to 100%. Each inline property we touch is saved and restored one by one, so the site's own later style changes survive.

3. **Layout, "overlay" (opt-in).** The v1.1 method: move the target into a fixed black `<div>`, leaving a comment placeholder to move it back to. Never used for iframes (moving one reloads it) or shadow-DOM content.

4. **Click protection.** Capture listeners record the last pointer event. If the page calls `exitFullscreen()` within `CLICK_WINDOW_MS` of a click that didn't land on a control (`isControl`: buttons, links, ARIA roles, "fullscreen"/"exit"/"close" labels), the call is ignored. A key press after the click turns protection off for that call, so a site's own <kbd>F</kbd> shortcut still works. A link that wraps the whole player has its click `preventDefault()`ed. Player handlers still run.

5. **Re-renders.** While active, a MutationObserver watches for the target being removed. If a new `<video>` shows up within 4 ancestors of the old one, it is windowed instead. Otherwise we exit.

6. **Frames.** Child frames talk to their parent with `window.postMessage` and `{__wvfs: 1, type}` payloads:
   - child → parent: `hello`, `child-enter`, `child-exit`
   - parent → child: `state {disabled}`, `parent-exit`, `toggle`

   When a child enters, the parent windows its `<iframe>` element (`kind: "frame"`). The protocol nests to any depth.

7. **Settings.** `bridge.js` reads `storage.sync`, merges it with the defaults (`WVFS.merge`), works out `siteDisabled` for its own hostname, and dispatches `wvfs:settings` on `document` with a JSON **string** detail. Objects don't cross the Firefox world boundary, so it must stay a string. page.js sends `wvfs:hello` when it starts, in case it loaded after the bridge's first send.

8. **Popup.** It messages the top frame's bridge (`frameId: 0`) with `status` or `toggle`. The bridge asks page.js synchronously with `wvfs:query` and `wvfs:state` events.

## Rules

- **page.js must not leak into the page.** It is one IIFE and its only global is the non-enumerable `__wvfsInstalled` flag. Don't add globals, and don't load other scripts into the MAIN world.
- **The page can forge any event or message.** Nothing coming from the page or a frame may write to storage or reach extension APIs. The bridge only reads storage and forwards commands *to* the page.
- **Keep the default settings in sync** between `DEFAULTS` in `src/shared/settings.js` and the initial `settings` in `src/page.js`.
- **Restore everything.** Anything `enter()` changes, `exit()`/`teardown()` must undo. Use `setStyles()` for inline styles. Never write `style` attributes directly.
- **No new permissions** without a clear need and a README update. Today the only permission is `storage`, plus all-sites content scripts.
- **No remote code, no network requests, no analytics.** Store reviewers reject these, and they break the privacy promise in the README.
- **Same source for every browser.** Use `globalThis.browser || globalThis.chrome` in extension pages. Put browser differences in `manifests/*.json`, not in code branches, wherever possible.
- **Bump the version in both manifests** (`build.sh` refuses a mismatch) and add a `CHANGELOG.md` entry for anything user-visible.
- **Plain language in UI text.** Say "windowed fullscreen", not internal names like "inplace".

## Checks before you finish

```sh
for f in src/*.js src/*/*.js; do node --check "$f"; done
node --test tests/*.test.mjs
tests/run-harness.sh          # needs Chrome or Chromium installed
./scripts/build.sh
```

When you change behaviour in page.js, add a case to `tests/harness.html`. Then load `dist/chrome` and `dist/firefox`, open `demo/index.html` over http, and try every section by hand. Headless tests can't press real fullscreen buttons or check native controls.

## Releasing

1. Bump `version` in `manifests/chrome.json` and `manifests/firefox.json` and update `CHANGELOG.md`.
2. Commit, then tag `vX.Y.Z` and push the tag. CI tests, builds, and attaches the zips to a GitHub release.
3. Store submissions (Chrome Web Store, AMO, Edge Add-ons) are manual for now. See docs/PLAN.md.
